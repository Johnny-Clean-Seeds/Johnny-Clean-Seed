# Helper Gap Cause Ladder Job Contract V0.1

Status: HELPER_JOB_CONTRACT / CANDIDATE_CONTRACT / NOT_DOCTRINE
Date: 2026-06-13

## One Job

Detect helper gaps, stale helper surfaces, weak helper contracts, or helper-route contradictions, then name the lowest cause layer before any fix.

## Trigger

Use this contract when:

- the task would benefit from a helper but none exists;
- the helper exists but does not say one job, allowed actions, blocked actions, proof, and DoesNotProve;
- public notes, Chat Drop cards, anchors, helper scripts, or local files disagree;
- a helper/script fails or risks a false pass;
- user steering changes already-completed work and the stack must be replayed.

## Allowed Actions

- read exact helper files, front-door files, Chat Drop anchors, and scanner output;
- classify the lowest cause layer;
- create a bounded helper-gap packet;
- suggest or draft a helper card only after the gap is repeated, risky, cross-surface, or likely to recur;
- run read-only scanners;
- run intentional negative tests only when they are scoped, expected, logged, and do not mutate protected surfaces.

## Blocked Actions

- no cleanup, deletion, rename, overwrite, broad repair, Git, GitHub, automation, or doctrine promotion by this contract alone;
- no helper may promote itself;
- no `PASS`, `COMPLETE`, `DONE`, or green verdict after missing proof;
- no loading stale/support Chat Drop cards as current instruction just because they are top-level.

## Required Evidence

- helper files checked/read/used/skipped/missing/stale/contradictory;
- active task and one active object;
- lowest cause layer;
- exact path, command, hash, or transcript evidence;
- containment or fix;
- proof after fix;
- DoesNotProve.

## Exit States

- `HELPER_CAUSE_LADDER_CLEAR`: current helper lane looks coherent for the scoped task.
- `HELPER_GAP_DETECTED`: helper support is missing or too weak.
- `HELPER_STALE_DETECTED`: helper surfaces conflict or are visibly stale.
- `BLOCKED`: authority, safety, or path proof is missing.
- `YIELD`: the user must decide whether to promote, park, or reject the helper change.

## Does Not Prove

This contract does not prove a proposed helper is good, active doctrine, complete, safe for all tasks, or ready for broad automation.
