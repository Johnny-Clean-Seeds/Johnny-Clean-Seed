### 02 — Guard Membrane Light Scan

Run each guard as a quick protective question. Do not expand unless it fires.

`TOKEN_CUSTODY`
Question: `Is any receipt, hash, manifest, card, link, commit, or verdict word carrying more authority than it owns?`
Trigger: token overclaim, hash-as-quality, receipt-as-proof-all, support-card-as-doctrine.

`THRESHOLD`
Question: `Is the object jumping grade?`
Trigger: raw-to-doctrine, candidate-to-rule, script-exists-to-run, static-verify-to-runtime-pass.

`LADDER`
Question: `Is authority descending and proof returning cleanly?`
Trigger: lower object claiming higher authority; return path missing.

`ROOM_DOMAIN`
Question: `Is this being judged in the correct room/domain?`
Trigger: proof from one room used to prove another room’s claim.

`SEASON`
Question: `Is this gate, action, proof, or promotion firing too early or too late?`
Trigger: Mars/Jupiter/Pluto/Earth fired out of order.

`ELEMENT_MODE`
Question: `Is the run acting, holding, naming, or proving in the wrong mode?`
Trigger: Fire before custody, Air instead of Earth proof, Water instead of action, Earth before claim wording.

`GATE_CONDITION`
Question: `Is the selected gate clean, strained, fallen, or overreaching?`
Trigger: gate trying to decide outside its domain.

`THREE_FACE`
Question: `Is the gate showing pure face, shadow face, or repair face?`
Trigger: pure/shadow/repair distinction needed for live correction.

`SIGNAL_OMEN`
Question: `Is there an early signal that should be marked before damage?`
Trigger: weak sign, blocker sign, repeated omen, possible root trigger.

`WASH_LOGIC`
Question: `Is this dry inspection, custody placement, or wet mutation?`
Trigger: clean, move, delete, archive, rewrite, repair, install, commit, save, cleanup.

`ROPE_ROUTER`
Question: `Which rope pulls this object toward which player/gate?`
Trigger: primary planet is unclear or route scent is mixed.

`INVOCATION`
Question: `Are we lawfully calling this room, tool, source, method, or proof path?`
Trigger: tool hunger, room drift, source overload, method call without reason, Earth proof call involving force.

### 03 — Expand Triggered Guard Only

If no guard fires:

`GUARD_SCAN_CLEAR`

If one guard fires:

Expand that guard into a short card.

If multiple guards fire:

Choose the highest-risk guard first by this order:

1. `WASH_LOGIC` if mutation/delete/install/commit risk exists.
2. `TOKEN_CUSTODY` if proof/receipt/hash/card authority overclaim exists.
3. `THRESHOLD` if grade jump exists.
4. `LADDER` if authority path is missing.
5. `ROOM_DOMAIN` if wrong-room proof exists.
6. `SEASON` if action/proof/promotion timing is wrong.
7. `INVOCATION` if tool/source/method call risk exists.
8. `SIGNAL_OMEN` if weak signal needs watch/escalation.
9. `GATE_CONDITION` or `THREE_FACE` if the active gate is overreaching.
10. `ELEMENT_MODE` if the operating mode is wrong.
11. `ROPE_ROUTER` if primary player is unclear.

Layer Echo stays first regardless.

## Pass / fail rules

`PASS`

The suit passes if:

- Echo runs before other support tools.
- All support organs light-scan as guard questions.
- Only triggered support organs expand.
- No support organ becomes a planet.
- One primary planet is selected.
- One counterweight planet is selected.
- One Earth check is named.
- The final route is explicit.
- Stronger claims are blocked.

`FAIL`

The suit fails if:

- Echo is skipped.
- The run jumps straight to planetary judgment without guard scan.
- All support organs expand into a monster pile.
- A support organ becomes a planet.
- A planet becomes king.
- Earth proof is omitted for a material claim.
- A receipt/hash/card/manifest is treated as broad authority.
- A tool/source/method is invoked without reason, boundary, return product, and stop condition.
