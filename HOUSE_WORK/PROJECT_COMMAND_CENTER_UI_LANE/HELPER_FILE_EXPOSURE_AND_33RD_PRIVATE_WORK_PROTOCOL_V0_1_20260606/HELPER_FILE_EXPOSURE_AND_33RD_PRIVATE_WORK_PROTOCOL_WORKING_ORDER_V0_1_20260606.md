## 1. Core Thesis

`ANCHORS ORIENT. HELPER MAPS LOCATE. EXCERPTS WORK. THE 33RD PRESSURES. RECEIPTS PROVE. FULL SOURCE STAYS PRIVATE UNLESS THE TASK SPECIFICALLY REQUIRES IT.`

The house should not choose between tiny anchors and full source dumps. It needs a ladder:

1. start from an anchor
2. locate the right helper files
3. expose only the needed excerpt
4. run the right work method
5. return a receipt

Helper files are carriers. They route, constrain, explain, and prove. They do not act by themselves.

Actors do work only when assigned by packet or user command.

## 2. Scope

This working order applies to:

- ChatGPT planning, critique, and handoff writing
- Mule source-processing and custody/report work
- Codex or code-lane work when a packet names it
- command-center and review-packet jobs
- helper-file routing
- outside-source use
- private-work exposure control
- 33rd / Double-Triple deep-pressure work

This order does not install a live command center, promote doctrine, authorize mutation, or replace receipts/source custody.

## 3. Exposure Ladder

Use the lowest exposure level that can safely do the job.

`L0_ANCHOR`

Use for orientation only. Examples: active object, front-door pointer, status pointer, one-line source pointer, work key.

`L1_INDEX`

Use for locating work. Examples: helper surface map, route index, file set, manifest, source map, catalog, receipt index.

`L2_EXCERPT`

Use for actual work. Examples: the relevant section, line window, table row, receipt block, schema shell, method card section, needed source passage.

`L3_FULL_SOURCE`

Use only when the whole raw source is required for extraction, cleanup, source-to-L0 conversion, or proof-sensitive rewrite.

`L4_SEALED`

Use for material that should not be exposed to an outside worker except under explicit user approval or sealed review packet.

Default movement:

`L0_ANCHOR -> L1_HELPER_MAP -> L2_EXCERPT -> WORK -> RECEIPT`

Escalate to L3 only when L2 is not enough. Treat L4 as blocked unless explicitly approved.

## 4. Helper-File-First Rule

For house work, helper files come before outside sources.

Before large source-processing, command-center, custody, or review-packet work:

1. find relevant helper files
2. classify them
3. read only the layers needed
4. record which were found, read, used, skipped, missing, stale, or conflicting
5. use them to route the work
6. return a helper-use receipt

Do not replace helper-file preflight with generic outside research.

Do not call helper files agents.

Do not expect helper files to execute anything.

## 5. Outside Source Rule

Outside sources are allowed only when needed.

Use outside sources for:

- current product/tool behavior
- current OpenAI/Codex/MCP documentation
- external standards
- outside pattern comparison
- unfamiliar or uncertain terms
- web/source research requested by the user
- Roof-zone pressure testing when the packet asks for deep research or the risk profile requires it

Do not use outside sources by default when the job is internal helper-file routing.

If outside sources are used, the receipt must include:

```text
OutsideSourcesUsed: true
WhyOutsideSourcesWereNeeded:
SourcesConsulted:
WhatTheyChanged:
DoesNotProve:
```

If outside sources are not used, the receipt must include:

```text
OutsideSourcesUsed: false
Reason: internal helper-file and source packet were sufficient
```

Outside sources never override house source by default.

## 6. The 33rd / Double-Triple Pass

`THE 33RD` is a three-round pressure method. Each round runs:

```text
WALLS -> CEILING -> ROOF
```

The full method is:

```text
Round 1 - Discover:
  Walls -> Ceiling -> Roof

Round 2 - Pressure:
  Walls -> Ceiling -> Roof

Round 3 - Sew / Rebuild:
  Walls -> Ceiling -> Roof
```

Each zone leaves trace. No trace means no pass.

Each round reworks the prior round.

Round 3 is the best current rebuild, not permanent doctrine.

## 7. 33rd Trigger Rule

When the user says "deep research," default to the 33rd unless the user narrows the job or says not to.

Use full 33rd when:

- user explicitly invokes deep research
- source is large or messy
- the task is high-risk
- the task affects custody, proof, mutation, or command-center authority
- the task may become a handoff, packet, index, build spec, or doctrine candidate
- the work needs outside pressure
- shallow one-shot work would likely drift

Do not use full 33rd for ordinary small tasks unless explicitly requested.

Scale options:

- `33RD_FULL`: all 9 zones
- `33RD_MEDIUM`: one Walls/Ceiling/Roof pass with pressure and receipt
- `33RD_LIGHT`: quick visible/body + load-bearing + risk scan with receipt

## 8. Mule Packet Rule

Mule only uses the 33rd when explicitly packeted.

Do not score Mule against the 33rd if the handoff did not assign it.

Mule can still be required to perform helper-file preflight for large source-processing, command-center, custody, review-packet, or source-to-live work.

Mule output must prove:

- what source was read
- what helper files were found/read/used/skipped/missing
- whether outside sources were used
- what outputs were written
- what was not done
- what mutation flags remain false
- what DoesNotProve survives
- what next legal action is

## 11. Trace Rule

No trace, no pass.

A valid trace records:

- zone
- source used
- helper files used
- outside sources used or not used
- findings
- repairs
- parked items
- DoesNotProve
- next condition

Hidden internal reasoning is not a trace. A trace is a user-visible or file-visible accounting artifact.

## 12. Completion States

`33RD_COMPLETE`

All assigned zones ran, each left trace, the final output is written, DoesNotProve is preserved, and next legal action is named.

`33RD_PARTIAL`

Some zones ran, but source, helper, outside-source, time, authority, or receipt limits prevented full closeout.

`33RD_BLOCKED`

The work cannot proceed because required source/helper/authority/exposure/receipt conditions are missing or conflicting.

Partial is better than fake complete.

## 13. Stop Conditions

Stop and return blocked if:

- active object is unknown
- source is missing
- helper files are needed but cannot be read
- raw source and helper files conflict on authority
- exposure level would exceed need-to-know
- outside source is needed but forbidden
- mutation risk exists without exact mutation authority
- receipt path is missing
- user approval is required but absent
- the job would install live files without separate approval
- a worker tries to claim doctrine or final acceptance from a draft
