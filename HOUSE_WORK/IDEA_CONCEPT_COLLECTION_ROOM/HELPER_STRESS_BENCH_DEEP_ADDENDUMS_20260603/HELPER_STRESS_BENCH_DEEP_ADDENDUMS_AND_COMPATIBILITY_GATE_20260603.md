## Purpose

Add the missing control layer around the helper stress bench so future helper testing does not become a broad runner, live mutation, vague trust claim, or false PASS machine.

The bench should test helpers, and it should also test new ideas before those ideas are allowed to alter the bench.

## Addendum 1 - Anti-Requirements and Compatibility Gate

Forbidden in this lane:
- run-all-first helpers.
- live destructive repo tests.
- real helper mutation before sandbox mutation exists.
- auto-repair after failure.
- auto-promote after one pass.
- PASS without final sentinel.
- route treated as authorization.
- broad git add, reset, clean, delete, or move.
- chaos before golden and negative fixtures.
- new rule silently weakening an older StopLine.
- unknown-authority helper execution.
- fixture without expected blocker class.
- fixture without forbidden behavior list.

Required before any new helper/rule/test/batch enters:
- object type.
- source and reason.
- affected rules, batches, helper tiers, fixtures, verdicts, stoplines, and trust states.
- duplicate, rename, contradiction, authority-expansion, and weakening scan.
- retest and regression decision.
- compatibility verdict.

Allowed verdicts:
- `COMPATIBLE_NO_RETEST`
- `COMPATIBLE_WITH_RETEST`
- `COMPATIBLE_WITH_RULE_UPDATE`
- `CONTRADICTION_OBJECT_REQUIRED`
- `BLOCKED_WEAKENS_EXISTING_RULE`
- `BLOCKED_AUTHORITY_EXPANSION`
- `BLOCKED_SCOPE_TOO_WIDE`

## Addendum 2 - Rule Collision Court

When two rules conflict, the newest rule does not win by default.

Collision row fields:
- `OldRule`
- `NewRule`
- `ConflictType`
- `WhichStoplineIsStricter`
- `WhichOneHasProof`
- `WhichOneHasBroaderBlastRadius`
- `Disposition`

Allowed dispositions:
- `KEEP_OLD`
- `ADOPT_NEW`
- `MERGE`
- `PARK`
- `CONTRADICTION_OPEN`

Core rule: new does not mean better, stricter does not mean correct, and proven fit decides.

## Addendum 3 - Coverage Gap Map

Every stress-bench packet must name what it still does not test.

Gap row fields:
- `TestFamily`
- `Covered`
- `NotCovered`
- `KnownBlindSpots`
- `FalseConfidenceRisk`
- `NextFixtureNeeded`

Initial named gaps:
- human-paste transcript noise.
- partial interrupted report.
- duplicate helper with same name in different folder.
- source lane trying to become active implementation.
- helper passing a tiny fixture but failing a long real file.

## Addendum 4 - Oracle / Judge Rule

No oracle means no proof fixture. It may still be exploration, but it cannot produce a PASS proof.

Oracle levels:
- `ORACLE_0_NONE`: exploration only.
- `ORACLE_1_MECHANICAL`: exact expected value or state.
- `ORACLE_2_BLOCKER_CLASS`: expected blocker class is known.
- `ORACLE_3_RELATION`: expected relationship between input/output states.
- `ORACLE_4_DIFFERENTIAL`: compare helper versions or helper A/B.
- `ORACLE_5_HUMAN_REVIEW`: human/assistant judgment.
- `ORACLE_6_COMPOSITE`: mechanical plus relation plus review for high-risk helpers.

## Addendum 5 - Bench Self-Test

The bench must test itself before it is trusted.

Self-test fixtures must catch:
- bad fixture.
- wrong expected blocker.
- missing forbidden behavior list.
- runner too wide.
- fake PASS in helper output.
- result ledger missing fields.
- weak spot not captured.
- regression fixture not created after repair.

## Addendum 7 - Combinatorial Interaction Gate

## Addendum 9 - Test Data Quality Gate

Test data must be ugly enough to matter and controlled enough to prove meaning.

Fixture quality checks:
- one clear primary injected fault.
- expected blocker class.
- forbidden behavior list.
- cleanup rule.
- proof it is not the real repo.
- source/hash identity where relevant.
- expected before/after state.
- edge cases appropriate to helper tier.
- no unrelated noise.
- judge/oracle assigned.

Bad fixture classes:
- `OVERNOISY_FIXTURE`
- `UNDERPOWERED_FIXTURE`
- `AMBIGUOUS_FIXTURE`
- `LIVE_DANGER_FIXTURE`
- `VIBE_FIXTURE`

## Addendum 10 - Failure Minimization / Shrink Rule

After a failure, shrink the fixture before repair when safe.

Allowed shrink verdicts:
- `MINIMIZED_REPRO_READY`
- `MINIMIZATION_NOT_SAFE`
- `MULTI_CAUSE_FAILURE_CONFIRMED`

Core rule: do not repair from a giant failing pile if a smaller failing object can be made safely.
