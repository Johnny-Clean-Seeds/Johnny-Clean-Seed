## Rules That Must Match Across Systems

1. A claim does not move work until it is split, typed, proof-scoped, authority-checked, and dispositioned.
2. A helper does not move work from role, name, registry row, or confidence. It needs bounded capability, exact input, return contract, and receiver assay.
3. A hash proves identity/custody, not quality, pass, approval, or authority.
4. A source feeds source ore unless a separate adoption path proves and approves it.
5. A support report is not an approval receipt. Classify proof surface before assigning trust strength.
6. Lower-layer repair needs evidence: exact failure coordinate, mechanism, same-chain rerun, and proof object closure.
7. Generated helper tools must prove parameter shape, zero-row behavior, stem identity, no hidden write authority, and what they do not prove.
8. Chat should carry one active object, one source/proof pointer, one next condition, and the recursive spine only when needed.
9. New tools/rules/methods must be locked, saved, parked, tested first, rejected, merged, or explicitly held until the active object closes.
10. Active guides and `CURRENT_TRUTH_INDEX.txt` are not rewritten by candidate rooms, helper packets, or good-sounding reports.
