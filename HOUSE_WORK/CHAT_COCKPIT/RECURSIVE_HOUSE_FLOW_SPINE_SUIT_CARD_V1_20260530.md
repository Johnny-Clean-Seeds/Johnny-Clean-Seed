# Recursive House Flow Spine Suit Card V1

Date: 2026-05-30
Status: CHAT COCKPIT SUPPORT CARD / NOT DOCTRINE
WorkKey: RECURSIVE-HOUSE-FLOW-SPINE-20260530-V1

## Wear line

Seed, gate, key, map, toolbelt, branch, proof, return.

## Carry

- one active object;
- one authority boundary;
- one key/hash or source identity when relevant;
- one proof/source pointer;
- one next condition.

## Use when

- files need to agree recursively without copying all rules everywhere;
- pathfinding, key/hash, Intake Gate, helper packets, or repair waves touch the same object;
- a branch is useful but must not split forever;
- a rule sounds useful but needs placement, proof, and return;
- root/top-level drops need explicit intake instead of watchers.

## Do

- start from the selected seed, not the whole house;
- use the front door before room diving;
- let Intake classify before conversion;
- let key/hash route through ledger/map before action;
- pick one toolbelt per movement;
- require branch join-back;
- leave proof or a named proof gap;
- park, block, prune, or return anything not carried forward.

## Do not

- touch Chat Drop files unless the manifest, stale/current proof, or user request requires it;
- make a universal map;
- load every proof receipt into chat;
- let keys spawn helpers directly;
- treat a hash as authority;
- call side hits FOUND;
- call skip-only repair;
- call a loop closed without return.

## Quick verdict

PASS: same seed returns with proof, bounded verdict, and next condition.
PARK: useful branch has a return trigger but is not current.
BLOCK: missing authority, proof, route, or safe boundary.
REPAIR: route works only after a named key/hash/path/intake fix.
