## Job

Give the house one small recursive shape so the front door, Intake Gate, key/hash routing, pathfinding, repair waves, helper packets, and proof closeouts agree without copying every rule into every file.

This is a pointer spine, not a new boss rule.

## One seed

Start from one little point:

`USER COMMAND OR SELECTED OBJECT`

Do not start from "the whole house."
Do not ask every room to speak at once.

Start with one object, one key/question, one authority boundary, one proof/source pointer, and one next condition.

## Core loop

`SEED -> FRONT DOOR -> INTAKE GATE -> KEY/HASH -> LEDGER/MAP -> TOOLBELT -> BOUNDED BRANCH -> PROOF -> RETURN -> UPDATE/PARK/PRUNE -> SEED`

The loop is closed only when the final next state can point back to the original seed or name why it cannot.

## Shared mirror slots

Active files do not need to repeat every rule. They should mirror the same small slots when touched, repaired, or promoted:

- ActiveTarget
- AuthorityScope
- ObjectPath
- ObjectKey or WorkKey
- Hash or source identity when relevant
- Lane or room
- Route or relation
- Proof/source pointer
- Stop condition
- Return path
- Next condition
- Disposition

If a tiny support file does not need every slot, it may carry only the proportional slots that keep the route honest.

## Cycle agreement

This spine aligns with the active guide cycle:

`target -> authority/scope -> object/location -> action -> evidence/proof -> risk/incident -> suspect/cause -> verdict/status -> next state/close/promotion -> back to target`

Use the active guides for full clean-seed checks. Use this spine to keep newer pathfinding/key/hash/intake support cards pointed at the same loop.

## Key/hash law

- Hash identifies an object state.
- Key requests route review.
- Ledger remembers state.
- Map names relation and direction.
- Event proves motion.
- Receipt proves a run or custody point.
- Verdict judges only after proof.
- Authority still comes from user command, lane boundary, and current house rules.

No hash alone promotes, authorizes, repairs, or proves PASS.
No key alone runs a helper.
No map alone commands work outside lane authority.

## Pathfinding chooser

Use the smallest pathfinding method that fits the active seed:

- Exact path, hash, registry, or ledger question: formal path search, cost check, and direct proof.
- Strong target scent but missing proof: Edward all-room triple pathfinding with FOUND / STRONG_SCENT / MEMORY_TRACE / SIDE_HIT / FOG_WALL labels.
- Changing terrain or stale currentness: replan before repair, then compare closure.
- Many duplicate/near-match routes: beam the best few branches, cut the rest, and leave parked triggers.
- Source/chat/helper output: Intake Protocol Stack before conversion into house language.
- Root drop or loose file: root holds, explicit intake pass hashes/keys/routes, no watcher.
- Helper action: Front Gate emits one bounded packet; helper returns route evidence.
- Branch work: declare branch key, parent key, proof, stop, join-back point, and return handoff.
- Repair wave: path-class review before repair packet; no broad repair.

## Branch and web rule

The house may branch, but every branch must know how it rejoins or why it parks.

Required branch fields:

- branch key
- parent key
- owner
- proof needed
- stop condition
- join-back point
- return handoff
- main route takeoff point
- close state

Allowed close states:

- MERGE_BACK
- END_LOCAL
- PARK_BRANCH
- BLOCK_BRANCH
- SUPERSEDE_BRANCH
- PROMOTE_TO_MAIN_CANDIDATE only by explicit decision and proof

## No closed-loop claim without return

Do not call a rule, repair, packet, report, or path closed unless it has:

- proof or a named proof gap;
- a verdict bounded to the checked object;
- a return path;
- a next condition;
- a parked trigger, block reason, or prune reason for anything not carried forward.

## No overcomplication rule

Before adding a new rule, ask whether an existing pointer closes the route.

Prefer:

`small spine + exact pointer + proportional proof`

over:

`new duplicate rule + broad partner rewrite + live-carry everything`

Do not make the assistant carry the whole house. Give it the seed, the spine, the right room, the right toolbelt, and the return path.

## Chat Drop boundary

Do not edit Chat Drop files just to mirror this spine.

Touch Chat Drop only when:

- the current manifest names the file;
- the file is stale against a newer load;
- the user explicitly asks for Chat Drop update;
- proof/custody requires a bounded stale/current disposition.
