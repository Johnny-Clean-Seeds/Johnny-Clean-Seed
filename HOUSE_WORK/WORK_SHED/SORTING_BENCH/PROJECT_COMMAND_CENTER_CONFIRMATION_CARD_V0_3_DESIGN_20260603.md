## Purpose

Design the card between resolved operator intent and any action.

The card must show:

- what the system thought the user meant
- what active object it resolved
- what mode it will use
- what files it will read
- what files it will write
- what files it will stage
- what command it will run
- what powers are blocked
- what proof is required
- what this does not prove
- what stop line applies
- whether explicit confirmation is required

## Confirmation required matrix

Required:
- save gate
- Git add, commit, push
- force-add ignored path
- execution of corrected script
- verifier execution
- implementation run
- mutation of active state
- writing operational pointer files
- creating UI files
- creating tools
- changing policy, registry, contracts, tool cards
- move, delete, rename, cleanup
- watcher start
- ACTIVE_GUIDES edit
- CURRENT_TRUTH_INDEX edit
- doctrine edit
- ambiguous pointer resolution
- stale pointer repair
- lower-layer issue repair that may mutate files

Not required:
- read-only inspect card with clear pointer
- status read with clear pointer
- design-only report after user explicitly says nxt

## Boundary

Design only.
No implementation.
No mutable confirmation-card engine.
No full UI.
No Micro 004.
No tool execution.
No Git mutation authorized by this design.
