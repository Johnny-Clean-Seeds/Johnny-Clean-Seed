## Purpose

When the root contains packets, drops, tools, receipts, media, research, transcripts, or idea folders, do not treat the root as one pile and do not treat every found file as active build material.

Sweep first, then inject by role.

## Sweep Order

1. List top-level root folders and loose files.
2. Count files and high-risk extensions.
3. Read each packet's read-first file, manifest, or receipt before body files.
4. Classify each packet as source, proof, tool, research, transcript, media, design packet, or active build lane.
5. Check whether a build-side rule, ledger, receipt, or pointer already exists.
6. Add the smallest missing build injection: candidate card, concept row, ledger row, or receipt.
7. Leave source packets in place unless a later bounded move request opens.

## Injection Targets

- `BRAIN_LEARNING`: reusable candidate rules and soft-suit cards.
- `HOUSE_WORK/IDEA_CONCEPT_COLLECTION_ROOM`: sweep ledgers and concept collection.
- `_LOCAL_CUSTODY_AND_RECEIPTS`: receipts, local placement proof, source custody proof.
- Existing build-specific rooms only when their readme or active work says they own the object.

## Minimum Build Injection

A root packet is considered injected enough for this stage when it has:

- source path;
- role;
- useful concept or boundary extracted;
- current build home;
- return trigger;
- proof need;
- DoesNotProve;
- StopLine.

If a packet has no useful build concept yet, inject only a parked ledger row. Do not force a rule.
