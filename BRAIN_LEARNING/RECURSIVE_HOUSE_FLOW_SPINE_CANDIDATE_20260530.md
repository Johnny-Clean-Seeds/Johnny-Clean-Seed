## Finding

The house already has the right ingredients, but they were scattered across active guide cycle law, organic pathing, Intake protocol stack, key/hash driver rules, branch join-back, Edward pathfinding, and repair-wave lessons.

The weird part was not that the rules disagreed. The weird part was that the front door did not expose one clean recursive spine that let those files agree without live-carrying all of them.

## Synthesis

The smallest shared shape is:

`SEED -> FRONT DOOR -> INTAKE GATE -> KEY/HASH -> LEDGER/MAP -> TOOLBELT -> BOUNDED BRANCH -> PROOF -> RETURN -> UPDATE/PARK/PRUNE -> SEED`

This turns "all things mirror all things" into a proportional mirror:

- active files share the same slots;
- small support files carry only the slots needed to keep the route honest;
- deeper files stay load-if-needed;
- proof/history stays behind pointers unless proof is the task.

## Why it helps the assistant

The assistant fails less when it does not need to reconstruct:

- what object is active;
- which rule has authority;
- whether a file is source, proof, guide, support, or stale copy;
- whether a key means action or lookup;
- whether a hash proves identity, not quality;
- where a branch returns;
- what counts as closure.

The spine makes those questions visible before movement.
