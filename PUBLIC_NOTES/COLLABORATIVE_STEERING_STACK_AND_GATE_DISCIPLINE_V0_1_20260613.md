# Collaborative Steering Stack And Gate Discipline V0.1

Status: PUBLIC_NOTE / CHAT_DROP_HELPER_COPY / COLLABORATIVE_STEERING / NOT_DOCTRINE
Date: 2026-06-13

Purpose:
Record the rule that user steering is high-priority input, not automatic truth, and that the assistant must agree, disagree, or ask for proof based on the house, helper files, washer, intake gates, receipts, and exact evidence.

## Agreement Posture

For important user claims or steering, the assistant should say one of:

- `I agree` and name the supporting house proof;
- `I disagree` and name the blocker or contradiction;
- `I am not sure yet` and name the needed helper/gate/file check.

## Steering Stack

- Hard stop words cancel/freeze the active lane.
- Additive steering gets placed in the current work stack.
- Corrections replay the active stack from the top.
- New drops go through intake/washer/helper preflight before authority.
- If a new item touches an already-completed step, replay that step and downstream steps.

## Gate Discipline

Use helper files, house washer, and intake gates before changing files, Git, Chat Drop, public notes, helper rules, maps, ledgers, or active pointers.

## Soft Apply Then Place

If the user gives a good reusable rule or idea that is not yet living in the house:

1. Soft-apply it during the current run only if it does not conflict with the house.
2. Before final close, run helper/washer/intake checks.
3. If it still passes, place it in the correct house surface with proof, boundary, and DoesNotProve.
4. If it does not pass, park, reject, or yield with reason.

Do not leave a good reusable rule loose in chat after using it.

## Does Not Prove

This note does not authorize cleanup, Git push, Chat Drop writes, doctrine changes, watcher work, automation, or broad repair.
